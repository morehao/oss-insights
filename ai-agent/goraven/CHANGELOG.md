# 变更记录

> 本解读对 GoRaven 的跨版本变更汇总；按版本倒序。上游未维护公开 changelog，条目以 `git tag` 与镜像发布为锚点；本文件只记录「解读内容」自身的基线变化与结论修订，不重复仓库提交历史。

## [v0.5.4]

依据：`v0.5.4`@`032c8b7`

本篇为**首次全量解读**（此前本知识库无 GoRaven 条目）。基线由 `select-baseline.mjs` 程序化选定：稳定 tag 中 semver 最高者为 `v0.5.4`（排除预发布与移动 tag），其工作树即本次的引用校验根。

文档集（`ai-agent/goraven/`）：

- `README.md` —— 总览：根因、核心能力清单、技术栈、项目规模、架构总览、启动流程、核心请求链路、核心模块导读表、设计亮点、不足与风险、可借鉴的设计。
- `agent-runtime.md` —— Agent 主循环与运行时：循环结构、停止条件与预算、Runner 生命周期与会话状态、SSE 事件流、子 Agent 委派、Go 并发模型。
- `context-management.md` —— 上下文压缩与剪枝：触发阈值、压缩策略、剪枝规则、两套机制的协作与代价、"不做记忆"立场的核实。
- `tools-and-sandbox.md` —— 工具系统与沙箱隔离：工具抽象与注册、Sandbox 接口与（实际只有）local 单实现、Shell 执行、路径穿越防护的缺口、命令安全校验的能力边界。
- `skill-system.md` —— Skill 体系与平台自描述：Skill 数据形态、发现与注入机制、系统提示词分层、8 个平台自描述 Skill 的设计意图、Marketplace 与分享模型。
- `plugin-system.md` —— 插件钩子体系：注册模型、四类生命周期钩子、执行语义与错误传播、工具中间件、内置 audit 插件、编译期注册与发布二进制零插件的现实。
- `mcp.md` —— MCP 接入：transport 与配置字段、工具发现与 schema 映射、调用链、stdio 进程生命周期与超时治理、安全边界。
- `knowledge-rag.md` —— 知识库与文档解析：文档转换管线、分块策略、"知识进入循环"的真实路径、llmwiki 方法论、无向量检索的短板。
- `multi-tenancy.md` —— 多租户与权限边界：认证机制、授权收口点、隔离强制层、共享机制、模型配额、自动化任务身份、预览模式风险。
- `data-model.md` —— 数据模型：三驱动一缓存选型、27 张表的 ER 图与核心表字段表、消息表的设计张力、隔离在数据层的表达、AutoMigrate 与种子/索引的演进边界。

- 引用总数 **1026 条**（README 43 + 9 篇子文档 983），经 `verify-references.mjs` 校验为 **OK=1026 / WEAK=0 / MISMATCH=0 / UNVERIFIED=0 / TRAVERSAL=0**——每条引用都带一段紧邻的源码指纹注释（首末行逐字、超 80 字符截断、含 `--` 或 `|` 时转 base64），锚点文本与真实源码行比对通过才算通过。
- Mermaid 图共 **26 幅**（README 3 幅 + 子文档 23 幅），全部通过 `check-mermaid.mjs` 的语法与渲染检查（ERROR=0 / WARN=0）。流程图统一用 `flowchart` 声明，避免 dagre 在 `graph` 声明下的布局报错。

### 解说范围与已知边界

- 关注面按用户确认的「标准」深度执行（核心模块覆盖率 ≥60%、次要模块 ≥30%），共 9 篇关注面子文档，覆盖 Agent 运行时、上下文管理、工具与沙箱、Skill、插件、MCP、知识与检索、多租户、数据模型。
- README 宣传与源码实现存在落差的点已在文中标注：`chroma_dir` 配置项无对应向量检索实现、Docker 沙箱只有一行空壳文件、插件发布时为「零启用」、`preview_user` 免登录且角色硬编码为管理员。
- 深读过程中发现的实现级风险（团队项目文件链路缺成员校验、MCP stdio 绕过命令安全校验且不回收子进程、runner 注册竞态等）已写入 `README.md` 的「不足与风险」与对应子文档。
- 前端 `frontend/src` 未做逐模块解读（本次关注面集中在后端与 Agent 运行时）；技能体系中的 `context: fork`、eino 内部中间件行为等超出仓库的结论已在该篇内标注为存疑待核实。
