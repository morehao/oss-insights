# CLI 设计与命令详解

> 本文为 Starred 项目的 CLI 设计与命令实现的深度分析。

## 一、总览

Starred 使用 **Click** 作为 CLI 框架，整个命令在一个 `starred()` 函数中完成，约 80 行核心逻辑。Click 的选择带来了优点的同时也有一些取舍：

| 维度 | 说明 |
|------|------|
| **CLI 框架** | Click（vs argparse / typer） |
| **配置传递** | `@click.option` 装饰器声明式定义 |
| **选项来源** | CLI 参数 > 环境变量（`envvar` 参数） |
| **版本展示** | `click.version_option` 读取 `__init__.py` 中的 VERSION |

## 三、核心实现细节

### 3.1 分类引擎（starred.py:81-99）

```python
for s in stars:
    if s.is_private and not private:
        continue
    if topic:
        for category in s.topics or [DEFAULT_CATEGORY.lower()]:
            ...
    else:
        category = s.language or DEFAULT_CATEGORY
        ...
```

**关键设计：**

- **私有仓库过滤** — 在分类前检查 `is_private`，`--private` 未设置时跳过
- **按 topic 分类** — 一个仓库遍历多个 topic，可能出现在多个分类下
- **按语言分类** — 语言为空时归入 `DEFAULT_CATEGORY = 'Others'`
- **描述截断** — `[:TEXT_LENGTH_LIMIT]`（200 字符），避免行过长
- **HTML 转义** — 自定义 `html_escape()` 仅处理 `<` 和 `>`，比标准库 `html.escape()` 更保守

### 3.2 Markdown 模板（starred.py:17-23, 25-33）

### 3.3 仓库写入模式（starred.py:118-132）

```python
if file:
    file_value = file.getvalue()
    gh = GitHub(token=token)
    try:
        rep = gh.repository(username, repository)
        try:
            content = rep.file_contents(f'/{filename}')
            if content.decoded != file_value:
                content.update(message, file_value)
        except NotFoundError:
            rep.create_file(filename, message, file_value)
    except NotFoundError:
        rep = gh.create_repository(repository, 'A curated list of my GitHub stars!')
        rep.create_file(filename, 'starred initial commit', file_value)
    click.launch(rep.html_url)
```

**关键设计：**

- **内容对比** — 仅在文件内容不同时更新，避免无意义提交
- **仓库自动创建** — 仓库不存在时自动创建含描述的仓库
- **首次提交** — 新仓库创建时使用独立的 commit message
- **自动打开** — 操作完成后调用 `click.launch()` 打开浏览器

**注意:** 这是 `github3.py`（REST API 客户端）在项目中唯一的用途。GraphQL 客户端（gql）不负责写入操作。

## 五、GraphQL 客户端实现

### GitHubGQL 类

```python
class GitHubGQL:
    API_URL = "https://api.github.com/graphql"

    def __init__(self, token):
        self.token = token
        headers = {"Authorization": f"Bearer {token}"}
        self.transport = AIOHTTPTransport(url=self.API_URL, headers=headers)
        self.client = Client(transport=self.transport,
                             fetch_schema_from_transport=True)
```

**初始化流程：**
1. 创建带 Bearer Token 的 HTTP Headers
2. 初始化 aiohttp transport（异步 HTTP）
3. 创建 gql Client，`fetch_schema_from_transport=True` 表示首次请求时自动拉取 GraphQL Schema

### 递归分页实现

```python
def get_user_starred_by_username(self, username, after='',
                                 topic_stargazer_count_limit=0):
    items = []
    result = self.client.execute(QUERY,
        variable_values={"username": username, "after": after})

    has_next = result['user']['starredRepositories']['pageInfo']['hasNextPage']
    end_cursor = result['user']['starredRepositories']['pageInfo']['endCursor']

    for repo in result['user']['starredRepositories']['nodes']:
        items.append(Repository(...))

    if has_next:
        items.extend(self.get_user_starred_by_username(
            username, end_cursor, topic_stargazer_count_limit))
    return items
```

**关键设计：**
- **递归而非循环** — 代码简洁但默认递归深度 = star 仓库数 / 100，Python 默认递归限制 1000，理论上可处理 100,000 个 star
- **after 参数类型** — 参数类型标注为 `str` 而非 `Optional[str]`，初始空字符串而非 None，GraphQL 能正确处理空字符串（等同于无 cursor）
- **topic 过滤在客户端** — GraphQL 查询不限制 topic，在 Python 侧过滤 `stargazerCount > topic_limit` 的 topic

## 七、典型缺陷与改进方向

### 当前问题

| 问题 | 位置 | 说明 |
|------|------|------|
| 双 API 客户端 | `starred.py` | 数据获取用 gql（GraphQL），写入用 github3.py（REST），两个重量级依赖维护同一接口 |
| 无单元测试 | 整个项目 | 仅依赖集成测试，无法快速验证逻辑变更 |
| 单线程分页 | `githubgql.py:84` | 递归串行请求，大量 star 时耗时线性增长 |
| 错误处理简单 | `starred.py:69-71` | GraphQL 异常仅打印红色消息退出，无重试或降级 |
| after 类型不严谨 | `githubgql.py:67` | `after: str = ''` 应为 `Optional[str] = None` |

### 改进建议

1. **移除 github3.py** — 写入操作可改用 gql mutation 或 `requests` + REST API 上传文件，减少一个重量级依赖
2. **添加单元测试** — Mock GraphQL 响应测试分类逻辑和输出格式
3. **并发分页** — 使用 asyncio 并发请求多页，对大量 star 用户有明显性能提升
4. **重试机制** — GraphQL 请求添加指数退避重试，应对 API 限流
5. **类型完善** — 修复 `after` 参数类型标注
